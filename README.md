# 信息过滤器 · Jev

**当前版本：0.4.4**（`npm run package` 生成 `dist/jev-x-filter-0.4.4.zip`，也可直接加载本目录）

用 **Jev（TypeSafe System One）** 的类型化决策在浏览器本地过滤 X（x.com / twitter.com）时间线、
回复区与推荐流里的**垃圾信息**，不是只过滤色情：色情/性交易引流、诈骗/博彩/荐股、
广告导流、标题党、低质 AI、重复文案农场，六类各自可开关。
除了「过滤」，它还做三件**整理**的事：**情绪言论**（愤怒/喜悦/支持/反对/悲伤/确认/表情）按线程折叠并标出类别，
**β（贝塔信息）** 把重复/类似/语义相同的内容折叠成一条，
**α（阿尔法信息）** 把「与评论区多数观点明显不同」的特殊观点标出来（只标记，不隐藏）。
命中即隐藏；**只有高置信度的类别才会动账号**（静音/拉黑），而且默认只演练、不真的点 ——
永不用一张图或一个关键词就动你的账号。

- 扩展形态：Chrome MV3，`chrome://extensions` → 开发者模式 → 加载已解压的扩展程序
- 判定引擎：[Jev](https://typesafe.ai/blog/introducing-system-one-models-and-jev) —— 不是聊天模型，
  你发 `state` + 类型化问题（Choice / Score / Noul），拿回带**概率与置信度**的答案
- 零构建：没有打包步骤、没有远程代码、没有运行时依赖；Jev 官方客户端以 MIT 原样内置

```
x.com 页面                       Service Worker（唯一网络出口）                外部
┌──────────────┐  推文结构   ┌──────────────────────────────────────┐
│ 内容脚本      │ ─────────▶ │ 预筛(正则/白名单/乱码名)               │
│ 抽取/隐藏/    │            │   ├─ 命中 ─────────────┐                │
│ 点菜单        │ ◀───────── │   └─ 未命中 → 预检(单问)│                │
└──────────────┘   判定结果   │ 图片分析(本地像素)      │               │  POST /v1/systemone
                              │        ↓               ↓               │ ──────────────▶ Jev 网关
                              │   Jev 四问 → 闸门 → 动作规划           │
                              │   缓存 / 预算 / 审计 / 黑名单           │
                              └──────────────────────────────────────┘
```

## 0. 更新日志

### 0.4.4 —— 情绪言论：折叠 / 隐藏 + 标出类别（愤怒 / 喜悦 / 支持 / 反对…）

用户：「把所有的情绪言论给折叠/删除，然后给予愤怒，喜悦，支持，反对，之类的信息。」

- **本地情绪分类器**（0 次模型调用）从 v0.4.2 的「附和」扩到 **7 类**：
  愤怒、喜悦、支持、反对、悲伤、确认、表情（纯 emoji）。
  判定保守：只有「整串恰好是一句情绪短语（可带加强语 / 语气词）」才算情绪言论 ——
  `我不同意，公开数据其实是反过来的`（讲理由）/ 疑问句 / 带数字或链接 / 超长文本**一律不折叠**；
  要折叠的是情绪，不是论点。
- **两种处理方式**（设置页 1.6 节选）：
  - `fold`（默认）：同线程同类情绪**第一条保留**并挂「情绪 · 愤怒」徽标（让你知道这是哪一类），
    其余折叠成 `情绪 · 愤怒：与 @… 的同类情绪回复相同 · 还有 N 条 · [展开]`；
  - `hide`：**全部折叠**（= 用户说的「删除」），一条都不显示，条上写明属于哪一类情绪。
- 不同类别各自归组（2 条愤怒 + 2 条喜悦 → 两条代表 + 两条折叠）；只在回复区、同一线程内生效；
  纯展示：不改 band、不改账号动作（不变量 I1），随时可以「展开」。

  所以「两个人恰好发同一句 6–7 字寒暄」不会被隐藏。
- 回归：新增端到端场景 G（分区夹具 + 短文案农场）与 6 条单测（农场阈值边界、分区信号不过白名单/自己发的、

### 0.4.0 —— α（阿尔法信息）与 β（贝塔信息）：折叠重复、标出特殊

- **β（贝塔信息）= 重复 / 类似 / 语义相同的信息 → 折叠，只显示一次**：
  同一段时间线里出现「换句话说的同一件事」（翻译、改写、转述、同一主张的复述）时，
  后来的那些折叠成一条细条（`与 @… 的内容相同 · 还有 N 条相似内容 · [展开]`），点「展开」可逐条还原。
  判定是**本地候选筛选（3-gram 相似度、同线程、同农场簇）+ 一次 Jev 批量调用（每个候选一个 noul）**，
  不是字符串相等 —— 这正是它比 v0.2 的精确农场更强的地方。
- **α（阿尔法信息）= 特殊信息，只标记不隐藏**：在回复区里，如果一条回复的观点与**多数评论明显不同**
  （且是有实质内容的观点，而不是刷屏），给它加一枚 `α · 与评论区多数观点不同` 徽标，
  这样你**不会错过少数派信息**；它不改变隐藏与账号动作。
- 两者都**纯展示**：任何情况下都不改变「隐藏 / 待确认 / 可动账号」的判定（不变量 I1 不变），
  也不改变 `band` 与 `accountAction`。
- 成本与开关：每次推文最多 1 次语义调用（本地没有候选就不调用），
  `semantics.maxPerMinute` / `maxPerDay` 限流；超预算或调用失败只跳过整理并计数，
  过滤结果照常返回。弹窗有「折叠重复信息（β）」「标记特殊观点（α）」两个开关，
  设置页 1.6 节可调阈值、候选数、参考评论条数，以及「时间线/回复区是否折叠」。
- **自动动作健壮性修复（真站反馈「自动动作失败：menu_item_not_found:mute」）**：
  根因是「先隐藏、再点 `⋯`」——推文子节点被 `display:none` 之后，`⋯` 按钮的 bounding rect 变成
  **0×0**，而 X 的菜单浮层要用触发按钮的 rect 定位，于是菜单要么不渲染、要么渲染到视口外。现在：
  1. 动作执行期间把 `⋯` 按钮临时恢复成「有盒子但不可见」（祖先链补 `display`，按钮 1px 离屏 + `visibility:hidden`），
     点完立即逐条还原 —— 推文依旧不可见、不闪动、不改变隐藏语义；
  2. 菜单定位改为「点击后**新出现**（或刚变为可见）的菜单」，不再取文档里第一个 `Dropdown`
     （X 会把关闭过的节点留在 DOM 里，里面还绑着**上一个账号**的处理函数）；
  3. 菜单项识别：`data-testid` 优先 + 多语言文案表（中/日/韩/西/葡/德/俄/阿/泰/越/印地…），
     且**先排除反义项**（`取消静音`、`Unmute`、`Débloquer`…）；
     「testid 与文案互相矛盾」的项一律跳过（宁可失败，也不 50% 点反）；
     文案里写着**别的 handle** 的项也跳过（防静音错人）；
  4. 打开菜单三级重试（原生 `.click()` → pointer/mouse 序列 → 两者都补），
     失败时把「菜单里实际有什么」写进审计与判定条 `title`，并用一句人话提示「可点『立即静音』重试」——
     绝不猜点。
- **β 的窗口身份兜底**：拿不到推文 id（例如扩展拿到的是没有 `/status/<id>` 链接的节点）时，
  用「作者 + 文案」的稳定哈希做窗口身份，`duplicateOf` 仍有锚点 —— 真站雪花 id 场景行为不变。

### 0.3.1 —— 近似去重的文案农场（对抗「同一句各插不同垃圾字符」）

真站样本：同一批农场账号在同一句里各插不同垃圾字符（`…没我骚蝎🐾…` / `…没我骚🐾💩…`、
`应该没人比我玩的开了吧…` / `没人比我玩的开了吧…`），还有账号把同一句写两遍 ——
**精确匹配的农场永远聚不成类**，而单条的预检概率正好压在阈值上下（实测 0.69 / 0.65 / 0.44）。

- **近似去重**：农场簇改用字符 3-gram 的**重叠系数**（默认 ≥0.8）聚类。
  实测对比：插一个字符的近似重复 Jaccard 只有 0.67（会把农场拆散），重叠系数 0.83，
  而完全无关的两段文案是 0.00；另加 0.5–2.0 的长度比护栏。
- **折叠重复行**：同一条推文里把同一句写两遍 → 折叠成一遍再比较（真站样本 `Shantel Just`）。
- **新结构信号「同推文重复句」**：单条推文里重复同一句（≥8 字符）+ 任一内容信号 → 隐藏。
- **农场结构证据分级**：≥3 个账号近似刷屏时不再要求额外内容信号（2 个账号仍要求，避免误伤）。
- **运行态持久化（重要修复）**：MV3 的 Service Worker 空闲会被回收，之前的农场簇、判定缓存与
  调用/动作预算全在内存里 —— 农场跨页面会重建，**限速也能被重启绕过**。现在把农场簇、
  每日计数与每小时动作窗口存进 `chrome.storage.session`，重启后恢复；
  分钟级窗口不带过去（会误伤新会话的配额）。

### 0.3.0 —— 从「黄推过滤器」升级为「信息过滤器」

- **类别化判定**：Jev 的问题从「是不是色情」扩成「属于哪一类垃圾信息」——
  九选一的类别 + 三条独立证据（色情 / 站外引流 / 欺骗）+ 危害程度评分（四级）。
- **六类可独立开关**：色情引流、诈骗/博彩/荐股、广告导流、标题党、低质 AI、刷屏农场。
  关掉某一类 = 该类别**不隐藏、不动作**（连兜底路径也一起失效，有单测锁住）。
- **可动账号的类别被显式限定**：只有色情引流、诈骗、广告导流能进入 `block` 档；
  标题党、低质、擦边诱饵**永远只隐藏**。账号动作还需要类别置信度 + 危害程度 + 一条硬度证据。
- **预检泛化**：单问从「机器人式成人诱饵」改为「垃圾/诈骗诱饵/低质填充」，
  阈值键 `baitReview/baitEscalate` → `junkReview/junkEscalate`（旧配置会自动迁移）。
- **预筛新增规则族**：荐股稳赚/博彩下注/标题党/广告导流/低质 AI 话术；
  已有的新闻语境降级、去符号匹配、农场检测、乱码账号名对这些新类别同样生效。
- 弹窗新增六类快捷开关；设置页新增「过滤类别」与危害程度/欺骗概率阈值；统计按类别计数。

### 0.2.1 —— 去符号（对抗 emoji 拆字）+ 农场阈值降到 2 个账号

真站样本：显示名写 `❤️处男免费❤️`，正文却是 `祝你有美好的一天🟧处🐕男🚹恭喜 发财` ——
**在关键字中间插 emoji**，于是「处男」这个词在原文里根本不存在，预筛 score=0、只能靠预检兜底。

- **去符号匹配（`stripSymbols`）**：规则同时对**原文**与「删掉 emoji/符号/空白后的密集文本」匹配，
  插字符、拆字、换标点全部无效（`处🐕男` → `处男`）。
- **弱特征按显示名 / 正文分开计分**：同一句黑话同时出现在名字和正文里，是两个独立信号（各 +1）——
  真站农场正是这个形态。
- **新增黑话弱规则**：`处男|破处|处女|炮友|女大|包夜|空降`。
- **农场阈值 3 → 2 个不同账号**：动手前仍然要求至少一条色情/诱饵/本地信号，
  所以「两个人偶然发了同一句长句」不会误伤；同一句文案的农场账号从第 2 个起就被隐藏。

### 0.2.0 —— 通用性 + 农场 + 静音开关

- **预检（模型先行）**：不再要求「关键词命中」才调用模型；没命中的推文也会被问一句廉价单问
  （`bait`：机器人式成人诱饵/性暗示自夸）。≥0.75 升级完整四问，≥0.65 隐藏成待确认。
  **这是「通用性」的根**：词表只决定花不花钱，不决定模型能不能看到。
- **文案农场检测**：同一段无实质内容的话被 ≥3 个不同账号在 30 分钟内复制 → 全部隐藏
  （含更早出现、当时被判放行的那几条，由内容脚本追溯隐藏）。归一化会吃掉 emoji/标点/大小写。
- **乱码账号名弱特征**：`yrmyzhcxvlkzpu` 这类随机串 +1 分（单独不隐藏）。
- **自动静音开关**：弹窗里新增 `自动静音` 与 `连「隐藏」档也静音`；后者打开后，
  隐藏档（含农场、预检命中）的账号也会被静音 —— 拉黑仍然只认 block 档。

## 2. 判定是怎么做的（四层，逐层加钱）

### 第 0 层：本地预筛（0 请求、确定性）—— 它只决定「要不要花钱」，不决定结论

`src/sw/prefilter.js` 用可读正则做**候选筛选**，不是判定。扫描范围是
**显示名 + 正文 + 卡片文案 + 图片 alt**（显示名单独计分）：

> ⚠ 真站踩坑：黄推会把引流信息**全部写在显示名里**（`🍑真实同城约p🍑主页联系🔞免费`），
> 正文写成无害的「那一夜你没有拒绝我😭🤣不是人机」（「不是人机」本身就是反检测话术）。
> 只扫正文的版本会让它连候选都不是 —— 一次模型调用都不会发生。现在显示名与正文一起进预筛，
> 且「约p」这类拉丁字母变体、`主页联系/看简介`、`🔞`、`不是人机` 都进了规则表。

- **强特征**：`约啪/约p/同城上门/同城联系/附近约/楼凤/外围/福利姬/裸聊/加电报/t.me、主页联系/看简介、onlyfans/escort/nudes/DM for menu…`
- **弱特征**：`资源/福利/真人/极品/学生妹、18+/explicit…`（一条弱特征不够，两条才送模型）
- **新闻语境降级**：命中 `警方/通报/整治/打击/专项行动/研究/报道…` 时，强特征降级为弱特征 ——
  避免把「警方通报打击色情网站」这类正常内容送进黑名单
- **直接跳过（一次请求都不发）**：白名单账号/关键词、自己发的、超短且无媒体、关闭了的 scope

### 第 0.5 层：预检（模型先行）—— 通用性的关键

**关键词表不是召回上限，只是廉价的怀疑。** 早期版本要求「预筛命中」才调用模型，于是黄推只要换个写法
（`比我好看的没我骚🔧👏`、把引流写进显示名）就不在词表里 → 模型根本看不到它 → 必然漏。这是结构性问题，
不是补几条正则能解决的。

现在对**没有被词表命中**的推文也问一句廉价单问（`bait`）：

> This post looks like bot-driven adult-content bait: the text is a sexually suggestive brag or tease
> with little or no real information, and/or the account name looks like random gibberish, in a way whose
> purpose is to get the reader to open the profile or follow.

| 预检概率 | 处理 |
| --- | --- |
| ≥ `baitEscalate`（0.75） | 再花一次完整四问，真正露骨的黄推仍可走到 `block` |
| ≥ `baitReview`（0.65） | 隐藏成「待确认」，**不做任何账号动作**（I1 不变） |
| 其余 | 放行 |

实测分离度（真实 Jev，`jev-latest`）：骚式自夸样本 **0.83**，普通日常 0.02、性教育 0.03、
泳装 0.18、正常小性感 0.13、健身 0.02 —— 阈值 0.65/0.75 有很宽的余量。

成本与开关：预检是一句单问（约 90 token 输入 / 12 token 输出，≈ 完整四问的 1/4），
`triage.sampleRate` 控制采样比例、`triage.maxPerMinute` / `maxPerDay` 控制总量；
**关掉 `triage.enabled` 就回到「只有候选才花钱」的 0 请求模式**（代价是通用性下降）。

另外有两类**不依赖词表**的本地信号：
- **乱码账号名**：`yrmyzhcxvlkzpu` / `cxvlu` 这类随机串（元音比例 <0.22 或连续辅音 ≥5）。
  它只算一条弱特征（+1），单独绝不足以隐藏 —— 两张真站截图的账号名都是这种。
- **显示名自身即色情引流**：`strongNameHit` → 至少隐藏成待确认。

### 第 0.8 层：文案农场（重复刷屏）—— 第三条不靠词表、也不靠模型

真站形态：回复区里 4 个随机账号在同一分钟刷同一句
`应该没人比我玩的开了吧🤣💖我福不黑不信你看`。单看任意一条，连模型都只能说「不确定」
（实测诱饵概率 0.47–0.54）；但「同一段无实质内容的话被 N 个不同账号短时间内复制」本身就是农场证据。

- 归一到「只留中文/字母数字」，所以换 emoji、换标点、改大小写都躲不掉
- 只统计**不同账号**（同一账号重复不算）；短于 10 个有效字符不参与（避免「哈哈」「太好了」误伤）
- 命中后 **全部隐藏**，包括比它更早出现、当时被判放行的那两条（内容脚本按归一化文案追溯隐藏）
- 需要至少一条色情/诱饵/本地信号才动手（避免把「同一句新闻标题」当 spam）；
  农场本身**只给隐藏档**，不拉黑 —— 是否顺带静音由「连隐藏档也静音」开关决定

### 第 1 层：图片信号（本地，不出网）

Jev 的 `state` **只能是文本**（官方类型定义里 `EntryType` 就是 string/JSON），它**看不了图**。
所以图片走两条路：

1. `src/sw/media.js`：Service Worker 里下载缩略图（`pbs.twimg.com`，带扩展权限，不受页面 CORS 限制）→
   `createImageBitmap` + `OffscreenCanvas` → 64px 采样 → 经典 RGB/HSV 肤色判据 + 4×4 网格主导度 +
   纯色块保护（`flatRatio > 0.9` 视为表情/占位图，直接忽略）
2. `src/sw/vision.js`（可选，默认关闭）：任何支持 `image_url` 的 OpenAI 兼容多模态端点，
   同样要求「概率 + 置信度」，回答不合规就当作无效、不修补

**图片信号永远不能单独触发隐藏或拉黑**（见 §3 不变量 I1）：沙滩、肤色背景、美食照都会命中肤色判据，
所以它只在文案已有本地信号时充当佐证。

### 第 2 层：Jev 类型化四问（`src/sw/classifier.js`）

一次调用问四个互相独立的问题（服务端并行），全部用英文写在 `instructions` 里
（上游明确说明模型在英文上最稳）：

| 问题 id | 类型 | 作用 |
| --- | --- | --- |
| `adult` | Noul | 这条内容是不是色情/色情引流（新闻、科普、治理报道不算） |
| `solicitation` | Noul | 是否把人往站外私密渠道（Telegram/微信/外链/DM）引 |
| `category` | Choice | 五选一：`adult_porn` / `adult_solicitation` / `suggestive` / `ordinary` / `other`，给出 `confidence` |
| `severity` | Score | 四级量表，便于事后调阈值 |

`state` 是英文元数据 + **原文不翻译**（`POST TEXT / AUTHOR / CONTEXT / media_alt_text /
link_card_text / 本地肤色占比 / 视觉模型概率`），上限 4000 字符。

### 第 3 层：闸门与动作规划（`src/sw/gate.js`，纯函数）

| 档位 | 条件（`a` = 成人概率，`c` = 类别置信度） | 结果 |
| --- | --- | --- |
| `block` | ① 类别 ∈ {色情, 引流} 且 `a ≥ 0.90` 且 `c ≥ 0.70`；或 ② 站外引流 ≥0.9 且 `a ≥ 0.90`；或 ③ **双确认**：`a ≥ 0.80` 且 `solicitation ≥ 0.80` 且 `c ≥ 0.95` | 隐藏 + 可执行静音/拉黑 |
| `hide` | 强类别且（`a ≥ 0.65` 或 `c ≥ 0.45`）；或 `a ≥ 0.90`；或图片裸露 + 本地文案信号 | 隐藏，不动账号 |
| `review` | `a ≥ 0.5`（模型不确定）；或弱文案 + 可疑图片；或**纯图形态 + 图片极可能裸露** | 隐藏并标「待确认」 |
| `ignore` | 其余 | 放行 |

`block` 的第 ③ 条是**真实模型实测后加的**：商业色情推广（如「OnlyFans 打折，链接在简介」）
在真实 Jev 上常给出 `色情 0.85 / 引流 0.86 / 类别置信度 0.96`，单条 Noul 摸不到 0.90；
与其放松单条阈值，不如要求**两个互相独立的问题同时过关**再升级。

**三条不变量**（写进代码注释并有单测守着）：

- **I1**：只有 Jev 的强判定 + 双闸门全部通过，才可能触发账号级动作。
  预筛命中、肤色启发式、视觉模型**单独出现**都最多到 `review`/`hide`，永不 `block`。
- **I2**：低置信度不会被「修补」成高置信度 —— 模型不确定就降级，不做二次猜测。
- **I3**：任何降级都写明原因（`reasons` + 中文标签），过滤条、审计日志、弹窗都能解释「为什么拦它」。

### 成本控制

- **预筛命中 / 只发图** → 一次完整四问；**未命中** → 一次廉价预检单问（可用采样率与预算限制，或整个关掉）
- 判定缓存：键 = 推文 id + 文案哈希 + **阈值指纹**（改了阈值自动失效，不会拿旧结论复用）
- 预算：每分钟/每天调用上限、每分钟图片分析上限、每小时/每天动作上限；超预算降级为「待确认」而不是乱拦
- 并发去重：同一推文并发只判一次

## 2.5 α / β：折叠重复的信息，标出特殊的信息

「过滤」之外还有两件**整理**的事。它们与过滤共用同一次判定的上下文，但**纯展示**：
任何情况下都不会改变隐藏与账号动作（这也是单测里锁住的不变量）。

### β（贝塔信息）：重复 / 类似 / 语义相同 → 折叠，只显示一次

- **本地候选筛选**（0 请求）：从最近 `semantics.beta.windowSize` 条推文里挑相似度高的作为候选 ——
  归一化文本的 3-gram 重叠系数 ≥0.45、或同一条推文下的回复（同 `threadId`）、或同一农场簇。
  **没有候选就不调用模型**。
- **一次 Jev 调用判定**：对每个候选问一个 noul（「是否表达同一信息/同一主张；翻译、改写、转述都算同一」），
  取最大概率作为相似度。
- **动作**：`相似度 ≥ beta.threshold`（默认 0.7）→ 折叠成一条细条，
  写明「与 @代表账号 的内容相同 · 还有 N 条相似内容」，点 **展开** 可还原。
  `duplicateOf` 指向该组**最早出现**的那条（代表条），`groupSize` 是这组的条数。
- **作用范围**由两个开关决定：`foldInFeed`（时间线/推荐流）与 `foldInReplies`（回复区）；
  两个都关时不发 β 问题。

### α（阿尔法信息）：与评论区多数观点明显不同 → 只标记

- **前提**：只判定回复（`alpha.onlyInReplies` 默认开），且同一条推文下已看到 ≥ `alpha.minReferences`
  条参考评论（默认 3）—— 没有「多数」就谈不上「不同」。
- **判定**：一次 Jev 调用问两件事 ——「是否与参考评论的多数观点明显不同且是有实质内容的观点」（noul）
  与「差异显著程度」（score）。**本地护栏**：与多数参考的文本相似度必须 ≤0.5，
  避免把「跟着多数说的」标成 α。
- **动作**：命中 → 推文顶部一枚 `α · 与评论区多数观点不同` 徽标（含参考条数与显著程度），
  **不隐藏、不折叠**；α 命中优先于 β。

### 成本

每次推文最多 1 次语义调用（候选为空则不调用），`semantics.maxPerMinute`（默认 10）与
`maxPerDay`（默认 300）限流；与过滤调用一起计入总预算。超预算/模型失败只跳过整理并计数，
决策照常返回（`alpha`/`beta` 为 null）。

## 3. 图片与「黄推」的真实难点

- 纯图片黄推（文案只有一个字 + 色情图）：**Jev 看不了图，文本判定必然偏低** —— 实测这类样本
  `色情概率 0.21`，模型会老实说「不是色情文案」。所以这里不依赖模型：只要同时满足
  「只发图/纯链接形态」+「图片极可能裸露（肤色占比 ≥ 0.70）」，就隐藏成**待确认**（一键可还原，绝不动账号）
- 「极可能裸露」阈值默认 **0.70**：实测 0.62 会把泳装/海边照也判成裸露（样本 0.62 时只算「可疑」，
  需要本地文案信号配合才会隐藏）
- 图片分析按需触发：默认只对「预筛可疑」或「文案极短 / 纯链接 + 有图」的推文下载缩略图，
  不会把整条时间线的图都拉一遍
- 已知误伤面：沙滩、健身、哺乳、医学、肤色背景、大面积布料都会拉高肤色占比 —— 这正是它不能单独决定的原因

## 4. 隐藏与交互

- 隐藏方式：保留 `<article>` 本身、只藏它的子节点，并在内部插入一张判定条（不破坏 X 虚拟列表结构）
- 判定条显示：档位、`色情概率 / 类别置信度 / 图片肤色占比 / 本地特征分`、命中的中文原因、来源（模型/缓存）
- 三个按钮：`显示`（临时展开）、`误判（加入白名单）`（该账号以后直接跳过）、`立即静音/拉黑`（手动补一刀）
- 状态栏徽标显示当前标签页已过滤条数

## 5. 自动静音 / 拉黑怎么做的

弹窗里有一键开关：`启用过滤` / `自动静音命中账号` / `连「隐藏」档也静音` / `演练模式`，
顶部一行会实时显示当前模式（例如「武装：block + 隐藏档都静音」）。

| 开关组合 | 效果 |
| --- | --- |
| 演练模式开（默认） | 只记录「本应静音谁」，不点菜单 |
| 演练关 + 自动静音开 | 只有 `block` 档（模型高置信度色情/引流）静音 |
| 再加「隐藏档也静音」开 | `hide` 档（文案农场、图片+弱文案、升级后的诱饵）也静音；`review` 档仍然不动 |
| 自动拉黑开 | `block` 档改为拉黑（可叠加静音）；**`hide`/`review` 永远不会拉黑** |

- **纯界面点击**：点推文的 `⋯` 菜单 → 选菜单项 → （拉黑时）点确认按钮。
  不调用 X 的私有 API、不伪造请求、不需要 cookie
- **与语言无关**：拉黑优先认 `[role="menuitem"][data-testid="block"]`；静音没有 testid，只能按文案匹配，
  且**先排除 Unmute/Unblock/取消静音**这些反义项，避免点反
- **只点新出现的确认框**：X 会复用 `confirmationSheetConfirm` 给别的弹窗，所以点击前先快照已存在的确认按钮，
  只认拉黑后新出现的那个，并校验文案
- **关闭菜单**：Escape 要派发给 `document.activeElement`（派发给 `document` 在真实 X 上无效）
- **串行 + 限速**：菜单是页面级浮层，多条推文同时点会互相抢菜单，所以动作全部排队执行，
  并且有动作间隔 / 每小时 / 每天上限
- **幂等**：同一账号在同一页面只动作一次（DOM 复渲染不会重复静音）
- **自动记账**：凡是判到 `block` 档的账号都会写入黑名单（演练模式也写，方便事后核对），
  黑名单可在设置页导出/导入，格式是人可读的 JSON

## 10. 已知限制与风险（请读完再武装）

1. **账号动作有风控风险**：自动静音/拉黑会真的改你的账号。默认演练模式 + 限速 + 幂等是防护，但不保证
   不被风控；建议 `maxActionsPerHour` 不超过 20，且不要长时间挂着大批量动作。
2. **选择器会漂移**：X 改版会让菜单/确认框失效。所有定位集中在 `src/content/selectors.js`，
   失效时动作会记 `action_failed` 到审计日志，不会静默乱点；判定条上的失败提示会写明
   「菜单里实际有哪些项」（鼠标悬停可见），拿它就能定位选择器漂移。
3. **菜单里没有目标项时会失败而不是乱点**：如果 X 某个版本/某种语言下 `⋯` 菜单里没有「静音」
   （或你手动打开着别的推文的菜单），扩展会**放弃**并在判定条上留一句「可点『立即静音』重试」，
   不会去点一个语义不明的项。语言表覆盖了常见本地化，但若你的界面语言不在表里，
   请把失败提示 `title` 里的菜单项文案反馈到 issue。
4. **Jev 不是全能判定器**：上游明确说它在英文最强、在数学/日期之类任务上弱；它对**视频**和**图片本体**
   无能为力（这是文本模型的边界）。所以图片只能靠本地启发式或你自备的视觉模型。
5. **误判仍会发生**：性教育、艺术、健身、二次元擦边、方言黑话都可能被拦或被放过。
   请用「误判 → 加入白名单」和设置页的阈值慢慢调。
6. **成本**：候选推文每条一次调用。Zen 免费档够试水；长期用建议配预算上限（默认 30/分钟、800/天）。
7. **审计 webhook 会外发判定信息**（含作者 handle 与文案前 160 字），默认关闭。
8. **本工具只服务于你自己的时间线卫生**：它是个人过滤器，不是举报/批量打击工具。

## 11. 维护指南

- **遇到漏检先看是哪种**：① 没被隐藏 → 看审计里这条有没有 `decision` 事件：
  没有 = 连预检都没跑（检查 `triage.enabled`、预算、白名单、scope）；有但 `source=预检` 且 `bait < 0.7` = 模型不认为它是成人诱饵（可下调 `baitReview`，但先看对照组分数再动）。
  ② 被隐藏但没静音 = 只到了 `hide`/`review` 档（阈值或个人选择，属正常）。
  把确信是黄推的账号用过滤条上的「误判」按钮是反向操作，正向补充请加关键词或用黑名单导入。
- **阈值怎么调**：设置页 → 第 2 节「置信度闸门」。想更干净就提高 `blockNoul`/`hideNoul`；
  漏得多就降低。先看审计日志里 `待确认` 的样本再动。
- **关键词怎么改**：`src/sw/prefilter.js` 的 `STRONG_RULES` / `WEAK_RULES` / `NEWS_CONTEXT`，
  都有 `id` 与中文标签，改完 `npm test` 会立刻告诉你有没有误伤既有用例。
- **X 改版怎么办**：只改 `src/content/selectors.js`；`npm run verify` 里的夹具页面就包含菜单/确认框流程，
  改错会直接红。
- **换 Jev 网关**：设置页第 1 节，或写自定义 `baseURL` / `path` / `model`（默认 `/v1/systemone`，与官方客户端一致）。
