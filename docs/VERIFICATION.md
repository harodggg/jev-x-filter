## 1. 静态自检（`tools/check-sources.js`）

不需要浏览器，检查的是「打包事故」类问题：

- `manifest.json` 合法、MV3、引用到的每个文件都存在
- Service Worker 声明 `type: module`
- 权限最小化：只允许 `storage` / `alarms`；host 权限只允许 x.com/twitter.com、twimg CDN、四个已配置的 Jev 网关
- 内容脚本只注入 x.com/twitter.com（**没有** `<all_urls>`）
- 没有 `web_accessible_resources`
- 打包代码里没有 `eval` / `new Function` / 远程 import / 远程脚本引用
- HTML 没有外链脚本，本地引用齐全
- **内容脚本确实是传统脚本**（出现 `import/export` 就报错，否则页面上会直接语法错误）
- 所有 JS 通过 `node --check`（33 个文件）

## 4. 本轮验证抓到的真实问题

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 「测试连接」报 `import() is disallowed on ServiceWorkerGlobalScope` | MV3 SW 禁止动态 `import()` | `JEVX_TEST_CONNECTION` 里那句 `await import('./classifier.js')` 改为顶层静态 import |
| 动作日志里 `spammer1` 被静音两次 | 注入的判定条改变了 `article.textContent` → 内容签名变化 → 被误判为「节点复用」→ 重新判定并再次动作 | 签名只取作者/文案节点；账号动作按 `handle:kind` 幂等 |
| 演练模式占用了每日动作预算 | 计数放在 `kind !== 'none'` | 改为只有 `execute === true` 才扣额度 |
| 端到端收尾 `ENOTEMPTY` 删不掉 Chrome profile | 未等 Chrome 退出就删目录 | 等 `exit` 事件 + `rmSync` 重试 |
| 断言 `User-Agent: jev-systemone/...` 失败 | 浏览器把 `User-Agent` 当受限请求头，忽略脚本设置 | 文档标注为平台限制，端到端改为显式断言「UA 由浏览器接管」 |
| 商业色情推广（OnlyFans 促销）真实概率 0.85/0.86，单条阈值 0.9 → 只隐藏不静音 | 真实模型验证 | 新增「双确认」路径：两个独立 Noul ≥0.80 + 类别置信度 ≥0.95 才升级为 block |
| 纯图片黄推（文案「看」+ 色情图）真实文本概率仅 0.21 → 整条被放行 | 真实模型验证（Jev 看不了图） | 「只发图/纯链接形态 + 图片极可能裸露」→ 隐藏成待确认，仍不动账号 |
| 「极可能裸露」阈值 0.62 会把泳装照（实测肤色 0.62）判成裸露 | 真实模型验证 | 默认提到 0.70；泳装样本回落到「可疑」，需本地文案信号配合才会隐藏 |
| **文案农场刷屏**：4 个账号同分钟刷同一句，单条诱饵概率只有 0.47–0.54 → 整批漏过 | 用户截图反馈 | 新增 `src/sw/farm.js`：同文案 ≥3 个不同账号（30 分钟窗口，归一化吃掉 emoji/标点）→ `hide`；内容脚本按归一化键追溯隐藏更早的条目；配套「连隐藏档也静音」开关 |
| **缓存指纹不全**：切换「自动静音」后已缓存推文仍按旧配置动作 | 端到端场景 D 失败 | 指纹补上 `action`/`triage`/`farm`/`media`/`budget`；新增单测「改动作配置必须缓存未命中」 |
| 端到端测试自身的竞态：写完配置只 `sleep 600ms`，场景 D 拿到场景 C 的配置 | 同一轮失败 | `configure()` 改为轮询 Service Worker 真实状态直至生效 |
| **v0.2 的「强类别」假设不通用**：闸门只认色情类别，无法表达「诈骗可动账号、标题党不可动」 | v0.3 类别化重构 | 类别事实表 `categories.js` 单点定义 `accountEligible`/`hideable`/分组开关；闸门与 UI/统计/审计全部读它 |
| 关掉「色情」类别后，兜底路径（成人概率 ≥0.5、肤色、视觉模型、显示名引流）仍在隐藏 | 单测暴露 | 所有隐藏路径都加类别开关约束，并逐条加断言 |
| **emoji 拆字规避**：显示名写「处男免费」、正文写「处🐕男」，预筛 score=0（「处男」在原文里不存在） | 用户截图（第 4 轮样本） | 新增 `stripSymbols()`：规则同时对原文与「去 emoji/符号/空白后的密集文本」匹配；`处🐕男 → 处男` |

## 6. 没被自动化覆盖的部分（诚实清单）

- **关键词型绕过**：真站样本说明黄推会持续换写法（`约p`、`约🅿️`、拼音、emoji 夹字、把引流写进显示名/卡片）。
  预筛是白盒正则，能快速补；但**不要指望它穷举**，它是「决定是否问模型的廉价筛子」，
  真正的判定在模型那一层（所以显示名等新载体一定要进 state）。
- **真实 x.com 页面**：夹具页面复刻了推文结构、菜单与确认框，但真实站点的类名、虚拟列表行为、
  多语言文案都会漂移。上线前请先用演练模式在你自己的时间线上跑几天。
- **真实 Jev 网关**：主验证走 mock 网关；真实网关由 `tools/live-check.js` 覆盖（见 §5，含延迟与 token），
  设置页的「测试连接」也可随时验证你的 Key/额度。`state` 上限（约 32k token）本扩展按 4000 字符截断。
  不同网关/模型的**校准差异**仍可能有：换 Key 或换模型后建议重跑一次 `live-check`。
- **视觉模型适配器**：只做了注入式单测（请求体、回答校验、错误路径），没有对真实多模态端点做过调用。
- **拉黑确认框的中文文案**：`confirmationSheetConfirm` 是结构判定 + 文案校验，中文文案未在源码中确认，
  因此实现以结构为主、文案为辅。
- **风控行为**：无法在测试中验证 X 对自动化的容忍度；默认限速与演练模式是工程上的保守选择。
